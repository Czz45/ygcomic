# YGComic 书源（网络小说源）接入设计

> 调研时间：2026-11。目标：给小说阅读器加入「书源」——用户粘一个书源 URL（legado 格式 JSON），即可搜索、发现、阅读网络小说。

## 一、业界事实标准：legado（阅读 3.0）书源 JSON

几万条现成书源都是这个格式，直接兼容 = 直接能吃整个生态。核心结构：

### 顶层字段
| JSON 键 | 含义 |
|---|---|
| `bookSourceName` | 书源名称 |
| `bookSourceUrl` | 书源地址（唯一标识 / 相对 URL 的 base） |
| `bookSourceGroup` | 分组（玄幻/都市… 可逗号多组） |
| `bookSourceType` | 0=文本 1=音频 2=图片 3=文件 |
| `bookSourceComment` | 注释 |
| `header` | 全局请求头（JSON 字符串或 `@js:`） |
| `loginUrl` / `loginUi` / `loginCheckJs` | 登录相关（可选，多数源不需要） |
| `bookUrlPattern` | 详情页 URL 正则（判断哪些 URL 是书详情，用于「打开书」） |
| `customOrder` | 手动排序 |
| `enabled` / `enabledExplore` | 启用 / 启用发现 |

### 四大规则块（对应阅读四环节）
1. **ruleSearch**（搜索）— 配 `searchUrl` 使用
   - `bookList`（结果列表选择器）、`name`、`author`、`kind`、`wordCount`、`lastChapter`、`intro`、`coverUrl`、`bookUrl`、`checkKeyWord`
2. **ruleExplore**（发现/分类浏览）— 配 `exploreUrl` 使用，字段同上
3. **ruleBookInfo**（详情页）
   - `init`（预处理）、`name`、`author`、`kind`、`wordCount`、`lastChapter`、`intro`、`coverUrl`、`tocUrl`（目录页 URL）、`downloadUrls`
4. **ruleToc**（目录）
   - `preUpdateJs`、`chapterList`、`chapterName`、`chapterUrl`、`isVolume`（卷标识）、`isVip`
5. **ruleContent**（正文）
   - `content`（正文选择器）、`nextContentUrl`（下一页）、`title`、`replaceRegex`、`webJs`、`sourceRegex`、`imageStyle`

### 规则语法（选择器引擎 —— 这是核心工作量）
前缀决定解析模式：
- 无前缀 = legado jsoup 默认语法：`class.x`/`id.x`/`tag.x`/`text.关键字`，`@` 分隔步骤，`@text/@html/@href/@src` 取值，位置 `0/-1/[..]`
- `@css:` / `@@` = CSS 选择器（jsoup 兼容，支持 `:has/:not/:contains/:eq`)
- `@xpath:` / `//` = XPath 1.0
- `@json:` / `$.` / `$[` = JSONPath（JSON 接口型源必用）
- `@js:` / `<js>…</js>` = JavaScript（可调用 java.* / baseUrl / result）
- `##正则##替换##` = 净化替换；`:正则` = AllInOne 取列表
- 串接：`||`取首个非空、`&&`合并、`%%`交错、`@@`链式
- 列表首字符 `-` = 反序
- URL 模板：`{{key}}`搜索词、`{{page}}`页码、`{{(page-1)*20}}`JS 表达式、`<a,b>`分页、`,{options}`请求选项(method/body/charset/headers/webView)

## 二、当前项目现状（已核对源码）

- 现有 `SourceFolder` / `EngineSource` / `SourceKind` **全是本地漫画文件概念**（SAF URI、zip/rar/pdf/txt），与网络书源无关，不能复用。
- `HomeScreen.kt:18` 注释「以后放音乐导航与图源入口」——书源是规划中的空壳，尚无任何网络/解析代码。
- 没有 OkHttp / HTML 解析库依赖；没有书源数据表。
- 优点：小说排版引擎（小说正文 → 分页渲染）已成熟，书源只需把「章节正文纯文本」喂给现有 `rawText` 管线即可复用全部排版。

## 三、接入方案（分阶段）

### 阶段 0：基础设施
- 加依赖：OkHttp（网络）、jsoup（HTML/CSS/部分 jsoup 语法）、kotlinx-serialization-json（→ 也可选一个 JSONPath 库或用 jsoup 手写）。XPath 用 jsoup 的 `selectXpath`（jsoup 1.17+ 内置 XPath）。
- 数据表：`book_source`（id, name, group, url, json, enabled, order, type, lastUsed），`搜索/发现`结果不落库，书详情落 `Book` 表（新增字段 sourceId、bookUrl）。

### 阶段 1：书源管理 UI
- 设置 → 书源管理：列表（名称/分组/URL/启用开关），「+ 添加」两种方式：
  a) 粘贴单条书源 JSON；b) 粘贴 URL 拉取 JSON（`http get bookSourceUrl`）。
- 批量导入 legado 分享串（base64 或 JSON 数组），去重按 `bookSourceUrl`。
- 校验：导入时跑一次 `searchUrl` 拼装是否成立 + 必填字段检查。

### 阶段 2：规则引擎（核心）
类 `SourceRuleEngine`：
- `parse(ruleStr, doc/string, baseUrl): List<String>` — 按前缀分派到 CSS/XPath/JSONPath/jsoup-default/JS/正则。
- `getString` / `getStringList` / `getElements`。
- URL 模板渲染 `buildUrl(template, key, page, header, book, chapter)`。
- JS 用 Rhino（Android 上成熟、legado 同款）或 QuickJS；先支持 `result`、`baseUrl`、`java.ajaxToStr` 最小集。
- 先用**单一代表性源**打通：搜索→详情→目录→正文。

### 阶段 3：搜索 / 发现 / 详情 / 阅读 闭环
- 搜索页：跨书源并发搜（每源 concurrentRate 限速），合并结果（书名+作者+来源）。
- 详情页：抓 `ruleBookInfo`，展示书名/作者/简介/封面 + 「加入书架」「开始阅读」。
- 目录：抓 `ruleToc`，章节列表。
- 正文：抓 `ruleContent.content`（含 `nextContentUrl` 翻页拼接、`####`净化、替换规则去广告）→ 得到整章纯文本 → 复用现有 `NovelReaderScreen` 排版管线（把 rawText 来源从"本地txt"换成"网络章节"）。
- 缓存：已读章节正文落本地 DB（离线可读 + 省流量）。

### 阶段 4：高级（可选）
- `exploreUrl` 发现页分类浏览、`isVip` 标注、图片源（bookSourceType=2 漫画图源，复用现有漫画渲染）、Cookie/登录、`@js` 完整 Rhino。

## 四、关键设计决策
1. **兼容 legado 格式，不自造格式** —— 直接吃现成生态书源。
2. **正文喂纯文本给现有排版引擎** —— 排版零改动，只换数据来源。
3. **网络层可插拔**（接口 `HttpFetcher`），便于测试与换代理。
4. **首条源打通优先于全量规则** —— 先跑通一两个真实源，再补全语法分支。

## 五、风险 / 待定
- JS 引擎选型（Rhino vs QuickJS）与体积。
- JSONPath/XPath 覆盖面（自实现 vs 引库）。
- 站点反爬（UA/Referer/charset GBK）——header 与 charset 选项要支持。
- 书源质量（很多源失效）——需要「源诊断」功能：单独测试一条源的搜索/目录/正文。

## 六、下一步
先确认方向：**兼容 legado 格式 + 首条真实源端到端打通**。确认后从「阶段 0 依赖 + 阶段 2 规则引擎骨架 + 一个测试源」开始落地。
